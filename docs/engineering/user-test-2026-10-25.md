## Follow-up implementation and gates

The proposed0.4.1 follow-up expands bounded action/object/scope relations for the seven reproduced families. New controls cover explicit refusal, public signing keys, labelled fiction, reporting actual failures, user-selected integrations, approval-preserving policy edits and untrusted-data handling. A false alarm on prioritizing a tool for a user-selected current task was also reproduced: the old authority pattern treated the word `user` alone as an override qualifier. It now requires an actual precedence/exclusivity qualifier. No whole-field benign exemption was added.

`scripts/user-product-retest.mjs` evaluates both metadata surfaces and records injection outcomes separately from other security review signals. The data remains a development regression set after these fixes; passing it will not establish universal detection. CI runs it on all native Go matrices and all six npm OS/Node combinations, retaining earlier expectations unchanged.
