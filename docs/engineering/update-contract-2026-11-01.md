# Installation handoff and update contract

The reproduced failure is successful npm installation of 0.4.4 followed by plain `mcpsense version` running Go's older 0.3.0 executable. Package version and command resolution are different states. An update succeeds only when the installed payload is verified and the PATH-selected command resolves to the intended version.

The next candidate adds a Node-only global postinstall check, an explicit `mcpsense update` command and bounded, cached terminal update notices. This intentionally replaces the previous no-install-hook policy; npm still requires no Go compiler, native MCPSense executable or executable download. Local/project/npx installations are not allowed to migrate global files.

For normal global npm installation, an older regular Go binary in the user's configured Go bin directory can be identified from embedded module/version metadata without executing it. Preserve it in a unique backup, then bridge its command name to the verified npm entrypoint. Never edit PATH, delete the backup, alter unrelated Go tools, follow a target symlink or replace unknown/newer software. Fail visibly when a shadowing command cannot be safely repaired. Recognizable metadata is identification, not a publisher signature.

Explicit npm updates use the existing global prefix, pin the stable version agreed by npm/GitHub, install using npm with lifecycle scripts disabled, verify the new runtime/version, repair the identified shadow and verify PATH resolution. Native Go updates compile the pinned module into staging, verify it, replace the active identified native installation with rollback/backup, and verify command resolution. Neither route silently downgrades a newer installation or installs a second language toolchain.

Only interactive CLI scans and the human version command may refresh terminal notices. Offline scans, JSON/SARIF, help, init, verification, CI and piped invocations do not perform automatic update networking. A one-hour per-user cache and two-second budget bound notices; lookup/cache failures must not fail a security scan. Notifications write to stderr and never install anything. `--no-update-check` and `MCPSENSE_NO_UPDATE_CHECK=1` suppress them. Explicit updates always recheck the published channels, never trust a cached version as installation authority.

Acceptance must include actual PowerShell 5.1 command resolution with an old Go copy before npm, repeated global installation, preserved backups/unrelated files, safe refusal of unknown/linked/locked targets, self-update using real package replacement, independent native updates, and unchanged security/user workflows. Publishing the new candidate remains separate from implementation approval. Historical 0.4.4 receipts remain unchanged.

Primary references: [PowerShell command precedence](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_command_precedence), [npm lifecycle scripts](https://docs.npmjs.com/cli/v10/using-npm/scripts/), [npm installation layout](https://docs.npmjs.com/cli/v10/configuring-npm/folders/), [Go build-info format](https://go.dev/src/debug/buildinfo/buildinfo.go).
